# MCI 데이터 보존 수정 — mci2 검증 절차

기준: main 84c6cbd969c30ec23d4eeb6a1db1bd6387bbbcfa.
이 변경은 DB 접근 권한 강화 작업을 완료하지 않는다. Firebase 적용 규칙과 Cloudflare 설정은 아직 직접 확인하지 못했다.

## 변경 내용

- 기기 저장 실패·미전송함 파싱 실패를 성공으로 처리하지 않는다. 입력 폼의 내용을 유지하며 오류를 표시한다.
- 손상된 미전송함을 빈 데이터로 덮어쓰지 않는다. 공간 정리 때는 서버 전송이 확인된 항목만 지운다.
- 미전송함 영속 기록을 확인한 다음 서버 쓰기를 시작한다. 삭제 요청도 같은 검증을 거친다.
- 목록에서 카드 수정 시 첨부 사진·0인 생체징후를 유지한다.
- 일반 사상자 목록의 수정 버튼이 일반 사상자 초안을 사용하도록 바로잡았다.
- 공통 카드 폼은 편집 시작 시 독립된 기준값을 보관하고 실제 변경된 필드만 전송한다.
- 원래 작성자 author/teamId는 수정 때 덮어쓰지 않고 _updatedBy/_updatedTeamId로 수정자를 구분한다.
- 확인된 운영 호스트 mci.visanu81.workers.dev에서만 운영 DB 경로를 사용한다. mci2·미리보기·로컬은 mci2 경로를 사용한다. 새 운영 도메인을 쓰려면 PRODUCTION_HOSTS를 먼저 검토해야 한다.
- wrangler.mci2.jsonc로 mci2 배포 대상을 명시한다. 이는 접근 권한 격리가 아니라 오배포 방지 장치다.

## 자동 검증

실행: `node tests/run.mjs` (외부 패키지 설치 불필요).

실제 index.html에서 함수 본문을 추출하고 브라우저 저장소/Firebase 쓰기를 모의 구현한 회귀 검사다.
수정본 17/17 통과. 이전 main에는 같은 검사 중 11개가 실패했다(일부는 새 수정 경로/환경 설정 유무를 확인하는 검사).
실행 환경: 도구의 V8 JavaScript 런타임. 로컬 명령 실행 도구가 응답하지 않아 Node CLI에서의 실행은 아직 하지 못했다.
실제 Firebase Emulator, 브라우저 화면, Workers 런타임, 모바일 현장 검증을 대체하지 않는다.

## 테스트 배포

Cloudflare의 mci2 Worker에서 저장소 브랜치를 이번 수정 브랜치로 선택하고 다음 설정을 사용한다.
운영 Worker mci의 브랜치와 배포 설정은 변경하지 않는다.

- 배포 명령: `npx wrangler deploy --config wrangler.mci2.jsonc`
- 배포 대상 Worker 이름: mci2
- 브라우저 접속: https://mci2.visanu81.workers.dev
- Firebase 경로: mci2/incidents, mci2/archives, mci2/config
- 기존 mci2 Worker의 OCR Secret은 대시보드에서 유지 여부를 확인한다. 저장소에 값을 넣지 않는다.

실행 전 현재 Cloudflare 빌드 명령이 index.html이나 DB_ROOT를 치환하고 있는지 확인하고,
그 작업이 있다면 호스트 기반 경로 선택 코드와 충돌하지 않도록 제거/수정한다.
이번 작업에서는 이 배포 명령을 실행하지 않았다.

## 현장 재현 검사 (가상 정보만 사용)

1. 일반 사상자와 MCI 각각 사진 2장·호흡수 0을 넣은 카드를 만든다. 목록의 수정과 상세 모달의 수정을 각각 거쳐 메모만 바꾼다. 사진과 0이 유지되어야 한다.
2. 기기 A·B에서 같은 카드를 연다. B는 병원을 저장하고 A는 메모만 수정한다. B의 병원이 유지되어야 한다.
3. 통신을 끊고 카드를 등록한다. 전송 대기 표시를 확인한 뒤 새로고침하고 재연결한다. 미전송 기록이 같은 카드 키로 전송되어야 한다.
4. 별도 테스트 브라우저 프로필에서 저장소 한도 초과를 재현한다. 저장 실패 메시지가 나오고 입력 폼이 비워지지 않아야 한다. 기존 미전송 기록을 삭제해서 공간을 만들지 않는다.
5. 별도 테스트 프로필에서 미전송함의 JSON을 손상시킨다. 오류가 표시되고 해당 원본 값이 유지되어야 한다.
6. 테스트 입력이 Firebase 운영 경로 incidents/에 나타나지 않는지 Firebase 콘솔에서 확인한다.

## 남은 제한

- 같은 필드를 동시에 수정하거나 오래된 미전송 작업이 다른 작업 뒤에 재전송되는 경우까지 충돌을 해결한 것은 아니다. 다음 단계는 카드별 순서 보장과 서버 버전 검증이다.
- localStorage는 다중 입력 탭 사이의 트랜잭션을 제공하지 않는다. 다중 탭 큐 경쟁 및 용량 확장은 IndexedDB 전환과 함께 다룬다.
- 미전송 큐는 사상자 카드만 포함한다. 사고 개요·동원 현황·관리 기능의 오프라인 영속화는 별도다.
- 서버에서 검증한 사용자 역할/관서 권한, 재분류·이송 상태 변경의 감사 이력은 추가 구현이 필요하다.
- 운영 반영 전에 mci2 검증 결과와 Firebase 권한 전환 상태를 함께 검토한다.
