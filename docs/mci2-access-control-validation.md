# mci2 서버 권한 검증 — 연결 전 검토본

2026-09-11. 브랜치 `codex/mci2-access-control`; 기준은 mci2 배포 소스 `8125cae`.

## 현재 상태

서버 로그인 모듈과 테스트 전용 Realtime Database 규칙을 구현하고 검사했다. 기존 `index.html`, `worker.js`, 운영 규칙 파일은 변경하지 않았다. 새 모듈은 현재 사이트에서 호출되지 않으며, 실제 프로젝트·서비스 계정·진입 코드를 만들거나 등록하지 않았다. 따라서 현재 사이트의 인증 취약점이 해결된 상태가 아니다.

**security/database.test.rules.json을 공용 disester-f3669 프로젝트에 배포하면 안 된다.** 이 파일은 별도 테스트 프로젝트용으로, 기존 운영 경로 접근을 모두 거부한다. 현재 mci2 데이터와 기존 미전송함을 자동으로 옮기지 않는다.

## 구현한 구조

1. 단말은 진입 코드만 서버에 전송한다. role·agencyId를 함께 보내면 서버가 거부한다.
2. 서버는 Worker Secret의 HMAC 해시와 코드를 비교한다. 새 코드는 암호학적으로 무작위 생성한 최소 128비트 값을 사용해야 한다. 저장소에 있던 관서명/관리자명 기반 코드는 재사용하지 않는다.
3. 코드 확인 후 서버가 단말별 UID와 `/access/{uid}` 권한 기록을 생성한다. 코드 유효기간과 12시간 중 더 짧은 시간까지 승인한다.
4. 권한 기록 저장이 성공한 뒤 5분 유효한 Firebase custom token을 반환한다. 브라우저는 이를 `signInWithCustomToken`으로 교환해야 한다. 5분은 교환용 토큰 기한이며 로그인 승인 기한과 다르다.
5. DB 규칙은 테스트 환경 claim, 서버 권한 기록의 활성 상태·기한·관서·역할을 매 요청 확인한다. 클라이언트는 관리자여도 권한 기록이나 진입 코드 저장소를 수정할 수 없다.
6. 일반 사용자는 같은 관서의 열린 재난을 수정할 수 있다. 카드 생성·수정에 UID를 요구하고 원작성 UID는 유지한다. 타인 카드 삭제와 전체 재난 삭제는 제한한다. 관리자는 관리 작업을 수행한다.

## 검증

- `npm run test:rules`: Firebase Realtime Database Emulator 4.11.2에서 **62/62 통과**.
- `npm run test:auth`: Node.js에서 **17/17 통과**. 일회성 RSA 키로 서명과 검증을 수행하고 외부 통신은 모의 구현했다.
- 사용 데이터는 가상 정보뿐이다. 실제 환자 조회·쓰기는 하지 않았다.
- Java 21이 필요하다. `npm ci` 후 위 명령을 실행한다. 규칙 검사는 프로젝트 `demo-mci-access`, 주소 `127.0.0.1:19000`만 사용하도록 검사한다.

검사 범위: 익명·미승인·만료·회수된 권한의 접근 거부, 타 관서 접근·조회 조건 위조 거부, 읽기 전용 역할의 쓰기/삭제 거부, 클라이언트의 관리자 승격 거부, 작성자/수정자 UID 위조 및 필수값 삭제 거부, 종료 재난 수정 거부, 여러 관서에 대한 원자적 쓰기 전체 거부, 코드 저장소 접근 거부, 운영 프로젝트 설정 거부, 실제 요청 본문 크기 제한, 토큰 발급 전 권한 저장 확인.

## 연결 작업과 결정할 사항

- 별도 Firebase 테스트 프로젝트를 생성하거나 지정한다. 서버 모듈은 `mci2-`로 시작하는 프로젝트만 허용하고 기존 운영 프로젝트 및 DB URL을 거부한다. 테스트 데이터 복제 여부는 따로 결정하며 실제 환자 데이터의 자동 복사는 하지 않는다.
- 테스트 전용 서비스 계정 권한을 최소 범위로 부여한다. 서버 서명용 계정 JSON, MCI_CODE_PEPPER, MCI_LOGIN_RECORDS는 Worker Secret에 넣는다. DB URL과 프로젝트 ID는 공개 설정, AUTH_RATE_LIMIT은 필수 바인딩이다. 현재 모듈은 누락 시 503으로 거부한다. 레이트 리미터의 지역별 한계와 코드별 공격 제한은 연결 단계에서 추가 검증한다.
- 현재 관서 코드 관리 UI를 서버 API로 바꾼다. 코드 폐기는 이미 발급한 권한을 즉시 없애지 않으므로 해당 UID 권한도 회수해야 한다. 만료된 권한 기록 정리는 별도 작업이다.
- 앱의 익명 로그인과 공개 SEED 코드, localStorage 역할 복원을 제거한다. 로그인 성공 후 서버 권한을 구독하고 만료/회수 시 데이터 구독과 쓰기를 중단해야 한다.
- 재난 목록은 일반 사용자의 관서 ID를 조건으로 조회한다. 보관함·관리 구독은 관리자에게만 연결한다. 카드에 createdByUid/updatedByUid를 추가하고 기존 데이터는 승인된 이관 절차에서 보완한다.
- 본부 통합 관찰자·표출의 전 관서 조회는 아직 이 초안에 포함하지 않았다. 현재 테스트 규칙은 관리자 외 모든 역할을 단일 관서로 제한한다. 실제 적용 전에 승인된 전 관서 읽기 범위와 환자 상세/사진 공개 범위를 정해야 한다. 화면 마스킹만으로 상세 데이터 접근을 제한할 수 없다.
- 기존 팝아웃은 원창의 Firebase 로그인 계정을 공유한다. 서버에서도 표출 전용 권한을 강제하려면 별도 제한 세션 발급이 필요하다.
- 새 프로젝트/UID에 기존 미전송 작업을 자동 재전송하면 안 된다. 이전 큐를 보존하고 환경·UID를 포함한 새 큐와 분리해야 한다. 오프라인 중 승인 만료, 재로그인, 재연결 후 권한 회수도 앱에서 검증해야 한다.
- OCR에도 같은 권한 조회를 연결해야 한다. 현재 배포된 OCR는 익명 토큰 검증 구조다.
- 이 초안은 접근 제어 우선 작업이다. 피해·동원·조치 하위 자료의 전체 스키마 검증, 감사 이력, 동일 필드 충돌 해결은 완료하지 않았다.
