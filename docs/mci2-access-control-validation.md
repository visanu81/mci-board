## 구현한 권한과 화면

- `/api/auth/login`: 무작위 진입 코드의 HMAC를 서버 전용 `serverCodes`에서 확인한다. 코드 원문·역할·관서 정보를 브라우저 입력에서 신뢰하지 않는다. 권한 기록을 저장한 후 custom token을 발급한다. 세션은 최대 12시간 또는 코드 만료까지다.
- `/api/admin/codes`: 현재 승인된 관리자만 목록 조회, 무작위 코드 발급, 폐기를 할 수 있다. 새 코드는 192비트 난수이고 원문은 발급 응답에 한 번만 포함된다. 유효기간은 1~30일이다. 목록은 메타데이터만 반환하고 코드 원문은 복원하지 않는다.
- 관리자 화면은 발급·복사·표시 닫기·폐기 확인/취소를 제공한다. 이전의 직접 코드 수정은 폐기 후 재발급으로 대체했다. 코드 목록에서 관서 디렉터리를 구성한다.
- ETag 조건부 저장으로 동시 변경을 감지한다. 현재 로그인에 사용한 관리자 코드의 자기 폐기와 마지막 유효 관리자 코드 폐기를 방지한다.
- 권한의 `codeId`와 코드 활성/만료를 매 DB 요청에서 확인한다. 코드 폐기 시 신규 로그인, 기존 단말의 읽기·쓰기, 연결된 표출 세션이 차단된다. 이전 후보의 관리 코드 없는 구형 토큰도 거부한다.
- 일반 관서는 소속 관서에서 허용된 작업을 수행한다. 관서 관찰자(observer)는 소속 관서만 읽는다. 본부 관찰자(hq)는 모든 관서를 읽되 수정·코드 관리·보관함 접근은 할 수 없다. 관리자(admin)는 전체 관리 권한을 갖는다.
- `/api/auth/display`: 승인된 일반 사용자/관리자가 지정한 재난에만 표출 세션을 발급한다. 새 UID, display 역할, 재난 ID, 부모 UID와 만료를 서버가 고정한다. 부모 권한 회수·만료와 코드 폐기가 표출 권한에도 적용된다.
- 표출 창은 별도 Firebase 앱과 메모리 인증을 사용한다. 입력 창의 로그인을 교체하거나 입력 복구본을 덮어쓰지 않는다. 토큰은 URL·localStorage에 넣지 않고 출처·창·nonce를 확인한 postMessage로 전달한다. 새로고침 시 입력 창에서 다시 열도록 안내한다.
- `/api/auth/config`는 공개 웹 설정만 반환하고 API 응답은 캐시하지 않는다. OCR는 Firebase 서명과 현재 서버 권한을 확인하며 normal/admin만 호출할 수 있다.
- 카드 미전송 기록은 UID·관서·프로젝트에 연결한다. 다른 로그인으로 재전송하지 않고, 전송 토큰을 고정하여 계정 변경 중 다른 사용자 토큰으로 저장되는 일을 막는다. 권한 종료 때 MCI/일반 카드 초안은 복구 파일로 보존한다.

## 서비스 전환 전 남은 확인

1. 실제 Chrome/Edge의 두 창에서 표출 토큰 전달·입력 로그인 보존·새로고침 안내와 모바일 화면을 검증한다.
2. 사고개요·피해·동원·조치사항 저장/삭제도 영속 미전송함과 계정 고정 REST 전송으로 전환했다. 아직 저장 버튼을 누르지 않은 입력 폼의 세션 종료 후 복구, 여러 탭의 미전송함 동시 갱신, 재난 생성 및 관리자 쓰기의 계정 고정 처리는 남았다.
3. 관리자 종료/보관/재개와 두 단말의 동시 수정 흐름을 종합 검증한다. 종료 API는 조건부 잠금 후 백업하며 원본을 보존한다. 종료 재개(실패 작업의 재시도)는 지원하지만 완료한 재난의 재개설은 아직 제공하지 않는다. 같은 필드 충돌을 자동 병합하지 않는다.
4. 완전 오프라인에서 앱을 새로 열면 서버 설정·권한을 확인할 수 없어 새 로그인을 허용하지 않는다. 이미 열린 승인 세션의 카드 큐와 별도로 현장 재시작 요구를 확인해야 한다.
5. 이전 DB 데이터나 구형 미전송 큐를 새 프로젝트로 자동 복사하지 않는다. UID가 달라진 미전송 작업의 확인·이관 절차가 필요하다.

## 2026-09-11 — Multiple-tab outbox protection (v102-multitab-outbox)

## 2026-09-11 메뉴·입력 동선 개선 (v103)

MCI 화면의 주 메뉴를 상황판 / 환자 관리 / 이송 관리 / 더보기로 구성했다. 모바일은 하단 고정, PC는 상단 메뉴다. 재난 이름과 실제 Firebase 연결 상태를 상단에 표시한다. 연결 표시 변경은 입력 화면 전체를 재렌더링하지 않는다. 일반 재난 모드는 더보기에서 이동한다. 관찰자는 읽기 전용 상황판/더보기만 볼 수 있다.

환자 관리는 번호·이름·발견 장소·병원 검색과 중증도 필터를 제공한다. 목록에서 등록 화면으로 진입하며, 목록으로 돌아와도 작성 중인 초안은 유지한다. 기존 상세 모달/수정/삭제와 사진 입력을 재사용한다. ‘풀 카드’ 버튼은 ‘상세 입력’으로 변경했다. 한글 조합 입력 중에는 검색 결과 재렌더링을 보류한다.

이송 관리는 동일 mciCasualties 카드의 hospital/departTime/arriveTime/notTransported/notTransportedReason만 조건부 갱신한다. 별도 환자 복사본을 만들지 않는다. 관련 필드 전체의 기준값을 확인하여 동시에 바뀐 이송 정보를 덮어쓰지 않는다. 미전송함, 원계정 바인딩, 최신 스냅샷 충돌 처리를 그대로 사용한다. 병원 배정/출발/도착/미이송을 구분하며, 기존 상황판의 병원 배정 포함 집계는 ‘배정·이송 중’으로 명확히 표시했다. 미이송 사유 편집은 기존 상세 입력에 남겨두었다. 시각은 HHMM 또는 HH:MM, 다음 날 도착은 허용한다.

검증: 저장 회귀 36개 + 세션/카드 충돌·수명주기/신규 이송 단위 검사 61개 = 97개 통과. 신규 이송 입력을 포함한 Cloudflare 후보+실제 독립 Firebase 연동 30개 통과, 가상 계정·데이터 정리 오류 없음. 새 이송 필드가 실제 규칙을 통과하고 다른 임상 필드를 보존함을 확인했다.

실제 IAB의 가상 Firebase 화면에서 이송 저장 1회, 사진/원작성자/기존 메모 유지, 검색 빈 결과, 입력 중 목록 이동 후 초안 유지, 일반 재난으로 전환을 확인했다. 모바일 390×844 및 320×740, PC 1280×900 배치를 점검했다. 작은 화면의 실제 콘텐츠 폭 305px / 스크롤 폭 305px, 하단 메뉴 높이 60px로 가로 넘침 없음. 실물 휴대전화 키보드/장갑 조작과 실제 전광판 두 창 검증은 별도다.

검증 후보 094c7ed8-48bf-4d77-b9af-a6a92c17043f를 mci2에 100% 반영했다. 제공 중인 HTML/SW와 로컬 파일이 정확히 일치한다. 실전 mci 페이지는 이전과 SHA-256이 같다. 직전 테스트 버전 2d48b3ea-71ff-433e-b4ab-9aef97f5bfdb로 되돌릴 수 있다. Firebase 규칙/스키마 및 실전 데이터는 변경하지 않았다.


## 2026-09-11 관리자 직접 지정 코드·코드 교체 (v104)

새 코드 발급에서 직접 진입 코드를 지정할 수 있다. 입력을 비우면 기존 무작위 발급을 사용한다. 서버는 발급과 로그인 모두 앞뒤 공백 제거 및 NFC 정규화를 적용하며, 8~128자/내부 공백 및 제어문자 제외 정책을 동일하게 적용한다. 대소문자는 구분한다. 코드는 HMAC 키로만 보관하고 원문은 발급 응답에만 반환한다. 이미 사용된 해시 키는 폐기 여부와 관계없이 재사용하지 않아 과거 세션이 되살아나는 것을 방지한다. 기존 자동 코드, IP별 로그인 제한, 관리자 권한 및 Origin 검사는 유지했다.

각 코드 행에 ‘코드 변경’을 추가했다. 원래 관서·역할을 유지한 교체용 코드를 먼저 발급하며, 기존 코드는 이 단계에서 계속 사용할 수 있다. 새 코드로 접속 확인 후 ‘이전 코드 폐기’ → ‘교체 완료 확인’을 누른다. 기존 코드로 로그인한 단말도 차단된다는 안내를 표시한다. 현재 로그인한 관리자 코드의 교체 완료는 서버가 거부하며 새 관리자 코드로 로그인한 뒤 완료할 수 있다. 다른 관서 코드의 교체는 관리자가 접속 확인 후 완료한다. 만료된 교체 코드로 기존 코드를 폐기할 수 없으며, 변경은 코드 목록 ETag로 직렬화한다.

관리자가 재난방 ‘더보기’에서 바로 ‘관서 진입 코드 관리’로 이동할 수 있다. UI에서 직접 지정 입력란, 변경 대상 관서/권한 고정, 교체 취소 및 안내를 확인했다.

검증: 저장 회귀 36개, 코드 관리/로그인 44개, 세션/Worker/설정/전광판/종료 60개 = 140개 통과. 실제 Cloudflare 후보+Firebase 연동 36개 통과 및 정리 오류 없음. 한글 16자 미만 코드 로그인, 코드 중복 거부, 현재 관리자 교체 중 접속 유지, 새 코드 로그인 후 완료, 기존 로그인/세션 차단을 임시 관리자 계정으로 확인했다. 기존 사용자 코드는 변경하지 않았다. 앞선 로컬 연동 검사 두 번은 통신 오류로 중단되어 정리했으며, 검증 스크립트의 Firebase 토큰 교환에는 동일 테스트 ID에 한해 네트워크 오류 재시도를 추가했다.

배포 버전 ea106ed9-ebf2-4027-9bb5-72d7b43e8796 / v104-managed-codes. 실제 mci2 HTML/SW와 로컬 파일이 일치한다. 실전 mci 페이지 해시는 이전과 같다. 직전 테스트 버전은 094c7ed8-48bf-4d77-b9af-a6a92c17043f이며, 이 버전으로 되돌리면 16자 미만 직접 지정 코드는 로그인할 수 없으므로 주의가 필요하다. Firebase 규칙은 변경하지 않았다.


배포 후 실제 mci2 주소의 코드 전용 연동 검사 9개 통과, 정리 오류 없음. 배포 후 전체 연동 검사는 13개 통과 시점에 통신 오류로 중단됐으므로 전체 재검증 성공으로 기록하지 않는다. 배포 전 동일 후보의 전체 36개 성공과 배포 후 코드 지정/교체 9개 성공을 구분한다. 코드 전용 검사는 `MCI_LIVE_CODES_ONLY=1`로 실행한다.


## 2026-09-11 로그인 코드 기본 가림
로그인 입력란을 password 형식으로 변경했다. 보기/가리기 버튼에 명확한 접근성 이름과 상태를 부여했으며, 로그인 제출 시 다시 가린다. 재렌더링 시에도 기본값은 가림이다. 후보의 실제 브라우저에서 가상 문자열로 password → text → 제출 후 password 전환을 확인했다. 저장 회귀/스크립트 구문 검사 36개 통과. mci2 배포 후 HTML과 SW의 로컬 일치를 확인했다. 서버 인증/코드/실전 mci는 변경하지 않았다.
