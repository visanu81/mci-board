# mci2 서버 인증·관서 코드 관리 검증

2026-09-11. 브랜치 `codex/mci2-access-control`, PR #3.

## 현재 상태

별도 Firebase 프로젝트 `mci2-secure-visanu81`에 웹 앱, 싱가포르 Realtime Database, Authentication과 접근 규칙을 구성했다. 이메일·익명 가입과 과금 연결은 비활성이다. 운영 프로젝트 `disester-f3669`는 변경하지 않았다.

최신 Cloudflare 후보 버전은 `08e79469-fd72-4d37-a139-e616918aec57`(태그 card-conflicts)다. 서버 Secret과 코드를 `versions upload`로 함께 업로드했으며 서비스 트래픽은 전환하지 않았다. mci2 서비스 버전은 기존 `939f0bb6-e85c-4c34-8680-b9db6cad5cf2`를 유지한다. 후보 URL의 브라우저 Origin은 허용하지 않으므로 현장 로그인 주소로 안내하지 않는다.

## 구현한 권한과 화면

- `/api/auth/login`: 무작위 진입 코드의 HMAC를 서버 전용 `serverCodes`에서 확인한다. 코드 원문·역할·관서 정보를 브라우저 입력에서 신뢰하지 않는다. 권한 기록을 저장한 후 custom token을 발급한다. 세션은 최대 12시간 또는 코드 만료까지다.
- `/api/admin/codes`: 현재 승인된 관리자만 목록 조회, 무작위 코드 발급, 폐기를 할 수 있다. 새 코드는 192비트 난수이고 원문은 발급 응답에 한 번만 포함된다. 유효기간은 1~30일이다. 목록은 메타데이터만 반환하고 코드 원문은 복원하지 않는다.
- 관리자 화면은 발급·복사·표시 닫기·폐기 확인/취소를 제공한다. 이전의 직접 코드 수정은 폐기 후 재발급으로 대체했다. 코드 목록에서 관서 디렉터리를 구성한다.
- ETag 조건부 저장으로 동시 변경을 감지한다. 현재 로그인에 사용한 관리자 코드의 자기 폐기와 마지막 유효 관리자 코드 폐기를 방지한다.
- 권한의 `codeId`와 코드 활성/만료를 매 DB 요청에서 확인한다. 코드 폐기 시 신규 로그인, 기존 단말의 읽기·쓰기, 연결된 표출 세션이 차단된다. 이전 후보의 관리 코드 없는 구형 토큰도 거부한다.
- 일반 관서는 소속 관서에서 허용된 작업을 수행한다. 관서 관찰자(observer)는 소속 관서만 읽는다. 본부 관찰자(hq)는 모든 관서를 읽되 수정·코드 관리·보관함 접근은 할 수 없다. 관리자(admin)는 전체 관리 권한을 갖는다.
- `/api/auth/display`: 승인된 일반 사용자/관리자가 지정한 재난에만 표출 세션을 발급한다. 새 UID, display 역할, 재난 ID, 부모 UID와 만료를 서버가 고정한다. 부모 권한 회수·만료와 코드 폐기가 표출 권한에도 적용된다.
- 표출 창은 별도 Firebase 앱과 메모리 인증을 사용한다. 입력 창의 로그인을 교체하거나 입력 복구본을 덮어쓰지 않는다. 토큰은 URL·localStorage에 넣지 않고 출처·창·nonce를 확인한 postMessage로 전달한다. 새로고침 시 입력 창에서 다시 열도록 안내한다.
- `/api/auth/config`는 공개 웹 설정만 반환하고 API 응답은 캐시하지 않는다. OCR는 Firebase 서명과 현재 서버 권한을 확인하며 normal/admin만 호출할 수 있다.
- 카드 미전송 기록은 UID·관서·프로젝트에 연결한다. 다른 로그인으로 재전송하지 않고, 전송 토큰을 고정하여 계정 변경 중 다른 사용자 토큰으로 저장되는 일을 막는다. 권한 종료 때 MCI/일반 카드 초안은 복구 파일로 보존한다.

- 서버 로그인: 17개 통과.
- 세션·Worker·프로젝트 설정: 41개 통과.
- 코드 관리·표출 API: 14개 통과. 역할 위조, 다른 관서, 임의 코드 지정, 자기 폐기, ETag 충돌 포함.
- HTML 저장 회귀: 30개 통과. 사진·0 보존, 저장소 오류·손상 큐 보존, 스크립트 구문 포함.
- 실제 Firebase: 17개 통과. 관리자 코드 발급 → 새 코드 로그인 → 가상 재난 생성 → 본부 읽기/쓰기 차단 → 독립 표출 로그인 → 코드 폐기 → 실시간 세션 종료와 부모/표출 접근 차단. 구형 후보 토큰 거부도 확인했다.
- 실제 Cloudflare 후보 `3e47083f-cf28-41ba-8b36-c2db6a5933ce`에서도 위 17개 흐름 통과. 이후 도움말·관리자 입력 보존을 반영한 최종 후보에서는 공개 설정·Origin 차단·토큰 발급/교환·자기 권한 조회 5개를 추가 확인했다. 실제 레이트 리미터와 Secret을 거쳤다. 테스트 요청에서 Cloudflare 전용 IP 헤더를 제거한 후 검증했다(로컬 모의 요청에만 해당 헤더를 설정한다).
- 브라우저 가상 데이터: 관리자 로그인, 코드 발급, 일회 표시 닫기, 화면 내 폐기 확인, 폐기/만료 상태 표시를 확인했다. 목록 갱신 후 작성 중인 관서 정보가 보존되는 것도 확인했다. 입력 창에서 표출 버튼을 누른 후 입력 화면 유지도 확인했다. 현재 내부 브라우저에서 팝업 자식 창을 검사할 수 없어 실제 두 창의 postMessage 완료와 TV 화면은 별도 검증이 남았다.
- Worker 업로드 성공: 37.11 KiB 번들. 정적 업로드에는 index.html, secure-session.js, sw.js 변경만 포함됐고 비밀 파일·tests·security 소스는 제외됐다.
- 실제 시험은 생성한 가상 계정과 가상 재난만 사용했다. 검증용 데이터·계정·코드를 정리했고 운영 환자 데이터는 조회·복사하지 않았다.

## 설정과 재검증

테스트 서비스 계정 `mci2-login`은 새 프로젝트에서만 `roles/firebasedatabase.admin` 권한을 가진다. 키는 Git/정적 배포 제외 경로에 보관하고 Cloudflare의 `FIREBASE_SERVICE_ACCOUNT` Secret으로 사용한다. `MCI_CODE_PEPPER`도 Secret이다. `MCI_CODE_STORE=database`를 사용하며 기존 `MCI_LOGIN_RECORDS`는 현재 로그인 경로에서 사용하지 않는다.

초기 일반·관찰자·관리자 코드 3개는 서버 코드 저장소로 이전했다. 유효기간은 2026-09-18 02:17 UTC까지다. 코드를 폐기하면 진행 중 로그인도 차단된다. 코드가 모두 만료된 경우 인증된 운영자의 서버 설정을 통한 복구 발급이 필요하다.

실제 검증은 기본 단위 테스트에서 자동 실행하지 않는다. 비공개 설정을 준비한 뒤 PowerShell에서 `$env:MCI_LIVE_TEST_PROJECT='mci2-secure-visanu81'; node tests/live-managed.mjs`를 실행한다. `MCI_LIVE_WORKER_URL`을 해당 mci2 후보 URL로 지정하면 Cloudflare를 경유한다. 대상 프로젝트와 후보 URL을 엄격히 제한한다. 기존 `tests/live-firebase.mjs`도 이 관리 코드 검증으로 연결된다.

## 서비스 전환 전 남은 확인

1. 실제 Chrome/Edge의 두 창에서 표출 토큰 전달·입력 로그인 보존·새로고침 안내와 모바일 화면을 검증한다.
2. 사고개요·피해·동원·조치사항 저장/삭제도 영속 미전송함과 계정 고정 REST 전송으로 전환했다. 아직 저장 버튼을 누르지 않은 입력 폼의 세션 종료 후 복구, 여러 탭의 미전송함 동시 갱신, 재난 생성 및 관리자 쓰기의 계정 고정 처리는 남았다.
3. 관리자 종료/보관/재개와 두 단말의 동시 수정 흐름을 종합 검증한다. 종료 API는 조건부 잠금 후 백업하며 원본을 보존한다. 종료 재개(실패 작업의 재시도)는 지원하지만 완료한 재난의 재개설은 아직 제공하지 않는다. 같은 필드 충돌을 자동 병합하지 않는다.
4. 완전 오프라인에서 앱을 새로 열면 서버 설정·권한을 확인할 수 없어 새 로그인을 허용하지 않는다. 이미 열린 승인 세션의 카드 큐와 별도로 현장 재시작 요구를 확인해야 한다.
5. 이전 DB 데이터나 구형 미전송 큐를 새 프로젝트로 자동 복사하지 않는다. UID가 달라진 미전송 작업의 확인·이관 절차가 필요하다.

## 2026-09-11 현장 입력 저장 보완

사고개요·피해·동원·조치사항 저장/삭제에 기기 영속 저장과 원래 로그인 UID에 고정한 전송을 적용했다. 전송 대기는 서버 저장 완료와 구분한다. 동일 경로의 이전 미전송 기록이 있으면 뒤의 기록 전송을 보류한다. 이 순서 검사는 같은 브라우저 실행 흐름을 대상으로 하며 여러 탭 사이의 원자적 잠금은 아직 제공하지 않는다.

이번 변경에서 저장 회귀 30개, 세션 등 41개, RTDB 에뮬레이터 85개가 통과했다(합계 156개). 신규 검사는 오프라인 보관, 저장공간 부족, 토큰 갱신 도중 계정 변경, 재전송 순서와 타 관서·읽기 전용·종료 재난 쓰기 차단을 포함한다. SW 버전은 v97-field-outbox다. 당시에는 Git 브랜치에만 반영했다. 아래 안전 종료 후보에는 v98과 함께 포함됐다. 실제 서비스 트래픽은 변경하지 않았다.

## 2026-09-11 안전 종료 검증

/api/admin/close는 승인 관리자만 호출한다. 재난 전체를 ETag와 함께 조회하고 변경이 없을 때만 closure 잠금을 저장한다. 그 사이 입력이 도착하면 409로 다시 실행하도록 안내한다. 잠금 이후 일반 사용자와 관리자 모두 SDK/REST 직접 수정·삭제·잠금 해제를 할 수 없다. 브라우저에서 종료 표시를 위조하는 것도 금지했다.

잠긴 원본으로 고정 ID의 백업을 저장한 뒤 closedAt을 확정한다. 원본은 삭제하지 않는다. 잠금·백업·최종 응답 유실 후 재요청해도 동일 백업을 사용한다. 종료 백업은 클라이언트 삭제/변경을 금지한다. 실패 시 진행 목록의 ‘종료 재시도’로 복구할 수 있다. 기존 ‘초기화’도 같은 안전 종료를 사용하며 새 재난은 로비에서 생성한다. 이 기기의 미전송 기록이 있으면 종료를 막고, 다른 기기의 미전송 기록은 운영자가 확인하도록 안내한다.

검증: 종료 단위 검사 10개, 관리 API 16개, 저장 회귀 30개, 세션/Worker/설정 41개, RTDB 에뮬레이터 90개 통과(이번 실행 합계 187개). 에뮬레이터에서는 실제 REST ETag 충돌과 잠금 직후 입력 차단을 한 흐름에서 검증했다. 실제 Firebase에서도 21개 흐름을 통과했다. 테스트 데이터와 계정은 정리했다.

새 테스트 프로젝트에만 규칙을 배포했다. Cloudflare 후보 cf953653-b910-4d26-96b0-4ca86acf1567 / v98-safe-close를 업로드했으며 mci2 서비스 트래픽은 기존 버전이다. 이전 보안 후보의 클라이언트 직접 종료는 새 규칙에서 차단된다.

제한: 원본 보존으로 저장량이 늘어난다. 종료 API는 재난 JSON 8 MiB까지 읽으며 초과하면 종료하지 않고 원본을 유지한다. 기기에만 남은 미전송 기록은 서버 백업에 포함할 수 없다. 완료 재난을 다시 열려면 별도 재개설 설계가 필요하다. 실제 두 창·모바일 UI 검증은 별도로 남았다.

Cloudflare 후보 cf953653에서도 실제 검증 21개가 통과했고 정리 오류는 없었다. 첫 시도는 6개 검사 후 네트워크 fetch 오류로 중단되어 가상 데이터를 정리했고, 새 가상 데이터로 전체 흐름을 재실행해 통과했다.

## 2026-09-11 모바일·표출 연결·동시 입력 검증

내부 브라우저에서 가상 데이터로 390×844의 간이/풀 카드 화면과 320×740의 상황판을 검사했다. 문서 가로 넘침은 없었다(각 client/scroll 폭 375/375, 305/305). 320px에서 상단 관리·반 변경 버튼 글자가 세로로 줄바꿈돼 축소 방지와 한 줄 표시를 적용했고 두 버튼 높이 30px을 확인했다. 실제 휴대전화 터치·키보드 검증을 대체하지 않는다.

표출 전달 코드를 display-session.js로 분리했다. 부모는 정확한 창·Origin·nonce의 준비 메시지만 한 번 받고, 연결 지연 시 안내한다. 시간이 지난 뒤 도착한 토큰은 보내지 않는다. 자식도 지정 부모·Origin·nonce만 허용하며 인증 실패/연결 지연 안내를 표시한다. 표출 관련 9개 검사와 저장 회귀 30개가 통과했다. 내부 브라우저가 window.open 자식 창을 검사 목록에 노출하지 않아 실제 두 창의 완전한 UI 검증은 아직 남았다.

## 2026-09-11 카드 동시 수정 충돌 보호

수정 화면을 열 때 원본 서버 레코드를 보관하고, 바뀐 항목의 원래 값을 미전송 요청에 함께 저장한다. 전송 시 최신 카드와 ETag를 읽고 같은 항목이 다른 값으로 바뀌었으면 자동 전송을 중단한다. 다른 항목의 변경은 최신 카드에 합쳐 조건부 PUT으로 보존한다. 읽기와 쓰기 사이의 변경은 최대 3회, 전체 12초 이내 재조회한다. 카드를 삭제한 경우 오래된 수정으로 되살리지 않는다. 수정 전 값이 없는 구형 미전송 수정도 보류한다.

충돌 요청은 자동/일괄 수동 재전송으로 우회하지 않는다. 현재 로그인에 속한 요청만 ‘충돌 확인’에서 서버 값과 내 입력을 비교한다. ‘내 입력 적용’은 표시된 서버 값을 기준으로 다시 조건부 저장하므로 그 사이의 추가 수정도 다시 잡힌다. ‘서버 값 유지’는 해당 요청을 전송 취소 상태로 보관한다. 로그아웃/권한 변경 때 비교 화면을 제거한다.

검증: 저장 회귀 32개, 세션/Worker/설정 41개, 충돌 전용 10개 통과(이번 실행 83개). 실제 Firebase 25개 흐름 통과, 생성 계정/데이터 정리 오류 없음. 실제 서버에서 오래된 동일 항목 수정 차단과 조건부 전체 카드 저장의 권한 통과/다른 필드 보존을 확인했다. 내부 브라우저의 가상 데이터에서 양쪽 값 비교, 내 입력 적용 후 전송 완료/사진·원작성자 보존, 서버 값 유지 시 미전송 배지 해제를 확인했다.
